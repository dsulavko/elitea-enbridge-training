Know when a Skill beats agent instructions

Station 3 Why Skills

One checklist, three agents, zero copy-paste

Reusable

Update the Skill and every attached agent picks it up.

Versioned

Named versions beside the always-present base.

Modular

Attach up to 5 Skills to one agent version.

Good candidates

  • PR-review checklist
  • Release-note style guide
  • "Formal tone" persona
  • Step-by-step QA procedure

Example: pr-review

## PR Description Review
Check: 1 Summary  2 Affected components
       3 Test coverage  4 Ticket reference
Format: ✅ Present: [item]
        ❌ Missing: [item] - [suggested addition]
Station 3 Build with AI

Three ways to create a Skill with AI

  1. Open Skills → + Create.
  2. In the General header click Generate with AI.
  3. Describe what the skill should do in plain words.
  4. Review the drafted Name, Description, Instructions → Approve → Save.
  5. Test in the side chat (ephemeral, not saved).
  1. Open an existing Skill → Edit with AI.
  2. Describe the change, e.g. "add a severity label per issue" → Generate Draft.
  3. Review the draft step by step.
  4. Save over the version or Save as Version to keep the original.
Published or embedded versions cannot be edited. Create a new version.
  1. In a chat: + → Modules → Skill Builder (and Ask User).
  2. Say: "Create a skill code-review-assistant for PEP 8 and security issues."
  3. Answer any clarifying questions.
  4. The skill opens in Canvas and appears as a chip in chat.

From chat you can also list, update, version, link to agents or delete skills.

Station 5 Basic integrations

Confluence, SharePoint, Outlook, Teams/Slack and PowerPoint all follow one pattern. Learn it once.

Credential → Toolkit → Use

Station 5 The pattern

Three moves, every time

1

Credential

Save the auth in Credentials. Keep secrets in Settings → Secrets and pick them from the dropdown.

2

Toolkit

In Toolkits & Indexes create the toolkit, choose the credential, tick only needed tools.

3

Use it

Add it to an agent, pipeline or chat. Test each tool individually first.

Credentials can be private (you) or project (shared). Prefer user-specific credentials for accountability.
Enabling every tool wastes tokens and confuses the model. Pick the few you need.

Station 6 Sharing chats

Four ways to share a conversation

Invite users

+ → Invite Users (team projects). They get a notification.

Public chat

Visible to all project members. Reversible, so decide with care.

Share link

Copy a link for colleagues who already have project access.

External link

Secure, read-only link for people outside ELITEA. View or revoke under Manage Links.

  • @name notifies a person (AI will not answer that message)
  • Folders are visible to the team; chats inside only to participants
Station 6 Roles & access

Least privilege, always

RoleCan do
AdminFull access, user management, all create / edit / delete
EditorCreate and modify content; no delete or admin
ViewerRead-only: use but not modify
MonitorTracks activity and usage
Invite people in Settings → Users. Batch edits supported.
Folders can add per-user exceptions: Read-only or No access. Exceptions only restrict.
Do not hand out Admin unnecessarily. Review roles regularly.
Station 6 Sharing agents & skills

Publish, fork, export

  • In the project: members use the agent and attach the project's skills.
  • Publish: agent ⋮ menu → Publish. A 3-step wizard runs an AI validation (issues, warnings, improvements) before it goes live. Unpublish any time.
  • Skills publish to the ELITEA Catalog the same way.
  • Fork between projects; Import / Export to back up or move.
Never publish with hardcoded credentials or project-specific values.
Station 6 Artifacts

Shared files in buckets

  • + Create Bucket: name starts with a letter; letters, numbers, hyphens; max 56.
  • Retention policy (days to years). Expired files are deleted and cannot be recovered.
  • Drag-and-drop upload, folders, 50+ previews; edit text, Markdown, CSV, DOCX in Canvas.
  • Agents read / write through the Artifact toolkit; chat attachments land in a default bucket.
Short retention without backups, and sensitive uploads, are the classic mistakes.

Key takeaways

  • Chat is the entry point; modules add power only when needed.
  • Skills hold reusable behaviour; agents combine goals, tools and skills.
  • Build with AI gives a solid draft in minutes. Review before you save.
  • Integrations: credential → toolkit → agent. Fewest tools possible.
  • Share deliberately: right project, right role, no hardcoded secrets.
